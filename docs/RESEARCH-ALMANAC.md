# 科研黄历：科研安排与投稿择日

0.11.0 将产品统一命名为“科研黄历 / Research Almanac”，调用名与发布文件夹为 `research-almanac`。科研安排与投稿择日沿用同一个 Skill 和本地记录库。默认入口生成一周科研黄历；投稿作为周计划中的可选辅助模块，原有单独投稿调用保持可用。

## 已实现的融合

| 层次 | 内容 | 入口 |
|---|---|---|
| 日常主界面 | 七天日期、六大学科、每日行动与产物、各学科节奏、经典原文与解释 | `weekly` |
| 项目安排 | 任务时长、依赖、截止、可用时间、固定安排与未排入事项 | 同一份 weekly 输入 |
| 投稿择日 | 精确操作窗口、朝向、八卦、个人星座、适用学术依据与原有完整报告 | 可选 `submission` |
| 单独投稿 | 原有排序、比较、选定、复核、实际提交记录 | `recommend` 等原命令 |
| 本地回顾 | 保存本次输入与结果，读取往期科研黄历和投稿记录 | `history-html` |

Agent 接收输入并运行本地脚本。HTML 只展示生成时保存的内容；日期切换、学科筛选和语言切换不会重新排程、调用模型或请求网络。完整投稿报告在同一离线 HTML 内按需展开，也单独输出为 `submission.html`。

## 输入与生成

最少只需明确 IANA 时区。实时调用不复制示例的 `now`：默认下一个当地周一至周日。`week_start` 可明确指定一个周一；保存后的 `week_end` 为周日，转换给旧投稿引擎时使用下周一作为不包含的结束边界。

~~~sh
node scripts/cli.js weekly examples/weekly.json --out runs/general-week
node scripts/cli.js weekly examples/weekly-project.json --out runs/project-week
node scripts/cli.js validate-weekly examples/weekly-project.json
node scripts/cli.js render runs/project-week/weekly.json en
~~~

[通用示例](../examples/weekly.json)与[项目示例](../examples/weekly-project.json)使用固定模拟日期。完整字段见 [weekly 输入结构](../schemas/weekly-input.schema.json)。

| 字段 | 用途 |
|---|---|
| `timezone`, `week_start`, `now` | 时区、可选目标周、实际计算时刻 |
| `discipline` | 默认显示的学科；`all` 展示六大学科 |
| `region` | `CN-mainland` 启用已保存的大陆假期表；`none` 使用常规周一至周五 |
| `tasks` | `id`、标题、预计分钟、依赖、最早开始、截止、优先级、产物与来源 |
| `availability` | 明确可用时段；空数组表示没有可用时间 |
| `excluded_intervals`, `fixed_events` | 不可用时间，以及必须保持的已定安排 |
| `preferences` | 日缓冲比例、每日任务上限、默认语言 |
| `submission` | 完整的原有投稿输入；只有确有投稿需求时才加入 |
| `submission_task_ids` | 投稿前需要完成的项目任务，不填写则不擅自推断哪些任务是投稿前提 |

准备任务已计划并不等于已完成。尚未完成的必需任务会使投稿结果保持条件状态；时间排在这些任务之后。如果某项必需任务无法排入，本轮不给投稿窗口。原有作者确认、硬截止和官方依据继续有效。

## 一周安排的规则

1. **真实约束先行**：固定预约、诊疗值班、连续实验、田间窗口、不可用时间、任务依赖和截止时间优先。
2. **明确估时后排程**：没有时长的任务进入待安排区；已完成任务可满足依赖，不重复占位。算法采用单人、任务不拆分的保守顺序排程，按依赖、已提供截止和优先级选择可排任务。它不保证找到所有组合中的最优解。
3. **保留余量**：默认日程预留 20% 缓冲，每日最多三项任务。这是可改的产品默认值。默认工作日可用时间为 09:00–12:00、14:00–17:00；用户明确提供的时段优先，即使在假期也会按输入安排。
4. **节奏随情境变化**：理清、推进、核查、交流、收口、恢复、轻读、接续共八类流程。按本周实际工作日位置组织；每个学科有对应行动与产物。科研任务有实际预约时，按项目安排执行，通用节奏只供组织工作方式参考。
5. **文化作为解释层**：历法事实按本地库计算，经典按工作主题编选。干支、建除和卦象不用于给学科打“成功分”。每条经典带原文、白话解释、现代联系与来源。
6. **投稿使用剩余时间**：从本周可用时段扣除固定安排、排除区间与已排科研任务，再与投稿自己的可用时段取交集。沿用旧引擎的硬截止、准备、学术依据、用户偏好及文化排序。周计划的范围覆盖嵌套投稿输入里的旧 `range`，共同使用此次计算时刻和时区。

明确提供的可用时段代表用户的实际安排；通用学科卡片不会自动变成已排项目任务。假期标签也不表示国外期刊或在线投稿系统关闭。

## 历法、出处与内容性质

**已验证事实**：`lunar-javascript@1.7.7` 计算上海时区的农历、干支、建除与节气。2026 年中国大陆节假日和调休来自[国务院通知](https://www.gov.cn/gongbao/2025/issue_12406/202511/content_7048922.html)，以来源和核验日随报告保存。其他年份使用有说明的工作日回退；其他时区保留当地周计划，不伪造中国历法结果。

**个人理解 / 设计建议**：六大学科文案、八类节奏、时间缓冲与任务上限均为项目编写的工作组织建议。经典来自既有 [bagua.json](../data/bagua.json)，按主题取读，不宣称执行了当日占卦。

**待验证假设**：通用任务是否适合具体项目，需要实际研究阶段、资料、预约与任务状态。这里没有“星期与录用率”的通用加减分，也没有学科运势分或个人录用概率。当前并未实现奇门、八字或梅花排盘。

既有科研黄历产品用于前期交互比较，正式实现没有复制其随机评分，也不依赖其在线服务。出处与调研结论保留在前期方案档案中；运行所需规则和任务库全部随此 Skill 分发。

## 输出和兼容

~~~text
runs/project-week/
  report.html              主输出：科研黄历＋展开式投稿择日
  weekly.json              保存的整周结果
  input.json               完整本次输入
  record.json              不可覆盖的输入与结果记录
  report.md / report.en.md 中英文阅读版
  manifest.json            版本、生成时间、输入摘要
  submission.json         仅启用投稿时：原引擎完整结果
  submission.html         仅启用投稿时：完整独立报告
  submission-windows.ics  仅存在候选窗口时：候选日历事件
~~~

新增记录使用 `record_type: weekly`；旧记录没有类型字段时仍按原投稿记录读取，不修改原文件。`history-html` 混合读取两类记录，展示时可选择；原工作台只编辑投稿数据。所有 HTML 都是生成时快照。新增调用或导出才会包含最新记录。

`runs/`、`.local-data/`、`.cache/` 均不提交 Git，发布包不携带私人历史。更新 Skill 时保留原来的 `.local-data/history/` 或继续指定同一个 `--history-dir`。旧 JSON 格式及原有投稿命令不改名。

## 验收标准

- 下周日期、跨时区、已知假期和未知年份回退正确；42 个学科日格与保存结果对应。
- 循环依赖、任务重名、错误时段被拒绝；未知估时如实保留；已排任务不越过截止、不重叠固定安排。
- 投稿复用原引擎结果，避开科研任务；前置任务未完成时不显示为已就绪。
- 中文/English、每日/整周、学科与历史切换只展示本地结果；原文和用户输入保持不变。
- 主界面紧凑，详细来源与投稿报告按需展开；手机端无页面横向溢出，宽表在自身区域内浏览。
- 新旧历史混合可读且不重写；两种模式的回归检查继续通过。

外部提醒、社交平台发布物料、多人资源优化和完整术数引擎保持后续功能，不因本次融合宣称已实现。
